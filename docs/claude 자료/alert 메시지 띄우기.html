Step 3

핵심 코드 설명

① message.html — alert 후 이동

<script th:inline="javascript">
    /*<![CDATA[*/

    var message = [[${message}]];
    alert(message);

    location.replace([[${searchUrl}]]);

    /*]]>*/
</script>

th:inline="javascript"

이 속성을 <script> 태그에 붙이면 Thymeleaf가 JavaScript 안에서도 동작합니다.

<!-- th:inline 없으면 → 문자열 그대로 출력 -->
var message = [[${message}]];   →  var message = [[${message}]];

<!-- th:inline="javascript" 있으면 → 실제 값으로 치환 -->
var message = [[${message}]];   →  var message = "글이 삭제되었습니다.";

[[${변수}]] — 인라인 표현식

HTML에서는 th:text="${변수}"를 쓰지만, JavaScript 안에서는 [[${변수}]]를 씁니다.

위치표현식예시
HTML 태그 안th:text="${변수}"<p th:text="${message}"></p>
JavaScript 안[[${변수}]]var message = [[${message}]];

/*<![CDATA[*/ ... /*]]>*/ — CDATA 블록

이 코드에는 3가지 기술이 섞여 있습니다.

th:inline="javascript"    → Thymeleaf
[[${변수}]]               → Thymeleaf
/*<![CDATA[*/ ... /*]]>*/  → XML/HTML 규격 + JavaScript 주석 트릭

CDATA가 왜 필요한가?

HTML 파서는 <script> 안에서도 <와 >를 태그 기호로 읽으려 합니다.
예를 들어 JavaScript에 비교 연산이 있다면:

if (count < 10) { ... }
//         ↑
//   HTML 파서가 이걸 태그 시작으로 오해할 수 있음

이런 문제를 막기 위해 CDATA 블록을 씁니다.
CDATA 블록 안의 내용은 HTML 파서가 건드리지 않고 그냥 문자로 취급합니다.

그런데 왜 /* */ 로 감쌌는가?

순수 CDATA만 쓰면 JavaScript가 오류를 냅니다.

<script>
    <![CDATA[         ← JavaScript는 이게 뭔지 모름 → 오류
        코드
    ]]>               ← JavaScript는 이게 뭔지 모름 → 오류
</script>

그래서 JavaScript 주석(/* */)으로 감싸서 JS가 모르는 부분을 무시하게 만듭니다.

/*<![CDATA[*/    ← JS 입장: 주석이라 무시 / HTML 입장: CDATA 블록 시작

    코드          ← JS도 읽음, HTML도 건드리지 않음

/*]]>*/          ← JS 입장: 주석이라 무시 / HTML 입장: CDATA 블록 끝

각 줄이 누구 눈에 어떻게 보이는가

코드JavaScript 관점HTML 파서 관점
/*<![CDATA[*/주석 — 무시CDATA 블록 시작 — 이제부터 안 건드림
JS 코드정상 실행텍스트로만 취급, 파싱 안 함
/*]]>*/주석 — 무시CDATA 블록 끝
두 언어를 동시에 속이는 트릭

/*<![CDATA[*/ → HTML에게 "건드리지 마", JS에게 "주석이야"

/*]]>*/ → HTML에게 "여기까지", JS에게 "주석이야"

현대 브라우저에서는 없어도 됩니다

현대 HTML5 브라우저는 <script> 안의 내용을 자동으로 안전하게 처리합니다.
실제로 CDATA 없이도 잘 동작합니다.

<!-- 현대 브라우저에서는 이렇게만 써도 문제없음 -->
<script th:inline="javascript">
    var message = [[${message}]];
    alert(message);
    location.replace([[${searchUrl}]]);
</script>

단, XML 기반 XHTML 문서이거나 구형 브라우저 호환이 필요한 경우엔 반드시 써야 합니다.
Thymeleaf 공식 문서에서도 권장하는 패턴이라 관례적으로 씁니다.

location.replace() — redirect와 같은 역할, 다른 주체

location.replace()는 redirect와 같은 결과지만 누가 처리하느냐가 다릅니다.

Spring의 redirect:는 서버가 브라우저에게 "다른 URL로 가라"는 HTTP 302 응답을 보냅니다.

location.replace()는 브라우저(JavaScript)가 직접 해당 URL로 이동합니다. 서버와 왔다갔다 없이 클라이언트 혼자 처리합니다.

alert() 순서

alert(message);              // 1. 팝업 먼저
location.replace(searchUrl); // 2. 확인 누르면 이동

alert()은 동기적으로 실행됩니다.
확인 버튼을 누를 때까지 다음 코드로 넘어가지 않습니다.
그래서 사용자가 확인을 누른 뒤에 location.replace()가 실행됩니다.

② 컨트롤러 — Model에 데이터 담아 message로 보내기

@GetMapping("/board/delete")
public String boardDelete(Integer id, Model model){
    boardService.boardDelete(id);

    model.addAttribute("message", "글이 삭제되었습니다.");
    model.addAttribute("searchUrl", "/board/list");

    return "message";
}

message와 searchUrl을 Model에 담아서 message.html로 전달합니다.
message.html에서 [[${message}]], [[${searchUrl}]]가 각각 값을 받아 사용합니다.

searchUrl에 "redirect:/board/list"를 넣으면 안 되는 이유

redirect:는 Spring 컨트롤러의 return 값에 쓰는 전용 문법입니다.

location.replace()에 "redirect:/board/list"가 들어가면 브라우저는 redirect:/board/list라는 URL로 이동하려다 404 오류가 납니다.

location.replace()에는 순수 URL만 넣어야 합니다.

Step 4

왜 이렇게 작성했는가?

왜 redirect 대신 message.html을 거치는가?

기존 방식

삭제
→ 서버 redirect
→ 목록

알림 없음

현재 방식

삭제
→ message.html
→ alert 팝업
→ 확인 클릭
→ 목록 이동

Spring의 return "redirect:..."는 서버가 즉시 다른 URL로 보내버립니다.
그 사이에 alert를 끼워 넣을 수 없습니다.
message.html을 중간에 두면 JavaScript로 alert를 먼저 처리한 뒤 이동할 수 있습니다.

왜 location.replace()를 쓰는가?

location.replace()는 현재 페이지를 히스토리에서 대체합니다.
뒤로가기를 눌러도 message.html로 돌아오지 않습니다.

location.hreflocation.replace()
히스토리기록에 남음현재 페이지 대체
뒤로가기message.html로 돌아옴그 이전 페이지로 이동
사용자 경험어색함자연스러움 ✅

초보자가 하기 쉬운 착각

th:inline="javascript"를 빠뜨리면 [[${변수}]]가 그대로 출력됩니다.

alert 창에 "글이 삭제되었습니다." 대신 [[${message}]]라는 문자열이 그대로 뜬다면 th:inline="javascript"가 없는 것입니다.

searchUrl에 "redirect:/board/list"를 넣으면 안 됩니다.

redirect:는 Spring 컨트롤러의 return 값에 쓰는 문법입니다.

JavaScript의 location.replace()는 이 문법을 모르므로 redirect:/board/list라는 URL로 그대로 이동하려다 404 오류가 납니다.

alert()이 비동기라고 생각하기 쉽습니다.

alert()은 동기적으로 실행됩니다.

확인 버튼을 누를 때까지 location.replace()는 실행되지 않습니다.

Step 10

이해도 확인 질문

  1. th:inline="javascript"를 script 태그에 붙이지 않으면 어떻게 되는가?

    [[${message}]]가 Thymeleaf에 의해 처리되지 않고 문자열 그대로 출력됩니다. alert 창에 "글이 삭제되었습니다." 대신 [[${message}]]가 뜹니다.

  2. model.addAttribute("searchUrl", "redirect:/board/list")로 하면 어떻게 되는가?

    JavaScript가 location.replace("redirect:/board/list")를 실행합니다. 브라우저는 redirect:/board/list라는 URL로 이동하려 하지만 존재하지 않는 경로라 404 오류가 납니다. redirect:는 Spring 컨트롤러 전용 문법입니다.

  3. alert() 이후 location.replace()가 실행되는 시점은?

    사용자가 alert 창의 확인 버튼을 누른 직후입니다. alert()은 동기적으로 실행되어 확인을 누를 때까지 다음 코드 실행을 멈춥니다.

  4. location.replace()와 location.href의 차이는?

    location.href는 이동 기록을 히스토리에 남겨 뒤로가기를 누르면 message.html로 돌아옵니다. location.replace()는 현재 페이지를 히스토리에서 대체해 뒤로가기를 눌러도 message.html로 돌아오지 않습니다.

  5. CDATA 블록의 역할은?

    JavaScript 코드 안에 <, > 같은 특수문자가 있을 때 HTML 파서가 태그로 오해하지 않도록 보호합니다. /* */로 감싼 건 JavaScript가 <![CDATA[를 주석으로 처리해 JS 오류가 나지 않게 하기 위함입니다.
