게시글 작성 페이지 추가

feat: 게시글 작성 페이지 추가 — Spring 수업

🔴 반드시 이해

  • @Controller
  • @GetMapping
  • return값 → View 이름

🟡 개념만 이해

  • Spring MVC 구조
  • ViewResolver
  • Thymeleaf

🟢 나중에 공부

  • DispatcherServlet

STEP 01

이번 Commit 한눈에 보기

이번 커밋은 Spring 프로젝트에 처음으로 웹 페이지를 연결하는 코드를 추가한 것입니다. 사용자가 브라우저에서 localhost:8080/board/write를 입력하면 게시글 작성 화면이 나타나게 됩니다.

이를 위해 두 가지 파일이 필요했습니다. 하나는 URL 요청을 받아 처리하는 Java 클래스(Controller), 다른 하나는 실제 화면을 그려주는 HTML 파일입니다.

이 커밋이 사실상 "Spring 웹 개발의 시작점"입니다.

STEP 03

핵심 코드 설명

@Controller
public class BoardController {

    @GetMapping("/board/write") // localhost:8080/board/write
    public String boardWriteForm(){
        return "boardwrite";
        // 쌍따옴표 안 = 어떤 html 파일(view)로 보내줄 것인지
    }
}
  • 초보자 /board/write 주소로 들어오면 boardWriteForm 함수가 실행되고, boardwrite.html을 보여줍니다.
  • Java boardWriteForm()은 그냥 String을 반환하는 일반 메서드입니다. Java 문법으로는 전혀 특별하지 않습니다.
  • Spring @Controller가 붙은 클래스 안에서 String을 반환하면, Spring은 그 문자열을 View 이름으로 해석합니다. ViewResolver가 templates/boardwrite.html을 찾아 브라우저에 응답합니다.
  • 설계 Controller는 "어떤 URL에 어떤 화면을 보여줄지"만 결정합니다. 화면을 직접 그리지 않습니다. 역할을 분리한 것입니다.
STEP 04

왜 이렇게 작성했는가?

왜 @Controller를 붙이는가?
붙이지 않으면 Spring은 이 클래스를 그냥 일반 Java 클래스로 봅니다. URL 요청이 와도 연결되지 않습니다. @Controller를 붙여야 Spring이 "이 클래스는 웹 요청을 처리하는 역할이구나"라고 인식하고 Bean으로 등록합니다.
왜 return "boardwrite"인가?
Thymeleaf 설정상 templates/ 폴더 + 반환값 + .html 을 자동으로 조합합니다. 즉 "boardwrite" → templates/boardwrite.html이 됩니다. 경로를 하드코딩하지 않아도 됩니다.
왜 @GetMapping인가?
HTTP 요청에는 여러 방식이 있습니다. 브라우저 주소창에서 URL을 입력하는 것은 GET 방식입니다. 나중에 폼 데이터를 서버로 전송할 때는 POST 방식을 씁니다. 지금은 "화면을 달라"는 요청이니 GET이 맞습니다.

STEP 07

초보자가 하기 쉬운 착각

return "boardwrite"가 HTML 파일을 직접 실행하는 것 같아 보이지만, 사실은 Spring에게 View 이름을 전달하는 것입니다. 실제로 HTML을 찾아서 브라우저에 보내는 건 Spring 내부(ViewResolver)가 합니다.
@Controller와 @GetMapping은 별개입니다. @Controller는 "이 클래스는 컨트롤러야", @GetMapping은 "이 메서드는 이 URL을 처리해"라고 각각 알려주는 것입니다.
templates/ 폴더 위치가 중요합니다. boardwrite.html을 다른 위치에 두면 Spring이 찾지 못합니다.
STEP 08

중요도 구분

🔴 반드시 이해

  • @Controller — Spring에게 이 클래스가 웹 요청을 처리한다고 알리는 것
  • @GetMapping — 특정 URL과 메서드를 연결하는 것
  • return "boardwrite" — 어떤 HTML을 보여줄지 결정하는 것

🟡 개념만 이해

  • ViewResolver — "boardwrite" 문자열을 templates/boardwrite.html로 바꿔주는 Spring 내부 컴포넌트
  • Thymeleaf — Spring에서 자주 쓰는 템플릿 엔진 (HTML을 동적으로 만들 수 있음)

🟢 나중에 공부

  • DispatcherServlet — 모든 요청을 받아 Controller에 전달하는 Spring의 핵심 컴포넌트
  • ViewResolver 구현체 종류
STEP 09

오늘 배운 것

  • @Controller를 붙이면 Spring이 해당 클래스를 웹 요청 처리 클래스로 인식한다.
  • @GetMapping으로 특정 URL을 메서드에 연결할 수 있다.
  • Controller 메서드가 String을 반환하면 Spring은 그것을 View(HTML) 이름으로 해석한다.
  • HTML 파일은 src/main/resources/templates/ 폴더에 있어야 한다.
  • URL → Controller → HTML 의 흐름이 Spring MVC의 기본 구조다.
STEP 10

이해도 확인 질문

정답은 바로 알려드리지 않습니다. 생각해보고 답해보세요.

  1. @Controller를 클래스에 붙이지 않으면 어떻게 될까요? /board/write로 접속하면 무슨 일이 일어날까요?

    Spring이 이 클래스를 인식하지 못해 URL 매핑이 등록되지 않습니다. /board/write로 접속하면 404 에러가 납니다.

  2. return "boardwrite";에서 "boardwrite"는 정확히 무엇을 의미하나요? 파일 경로인가요, 아니면 다른 무언가인가요?

    파일 경로가 아니라 View 이름입니다. Spring의 ViewResolver가 이 이름을 받아 templates/ + boardwrite + .html 로 조합해서 실제 파일을 찾습니다.

  3. @GetMapping이 아니라 @PostMapping을 썼다면 브라우저 주소창에서 접속했을 때 어떻게 될까요?

    브라우저 주소창 입력은 항상 GET 요청입니다. @PostMapping은 POST 요청만 처리하므로 매핑이 맞지 않아 405 Method Not Allowed 에러가 납니다.

  4. 지금 boardwrite.html에 <form> 태그가 없습니다. 작성 버튼을 눌러도 데이터가 서버로 전송되지 않는 이유는 무엇일까요?

    HTML에서 서버로 데이터를 전송하려면 <form action="..." method="post"> 태그가 있어야 합니다. <button>은 form 안에 있어야만 제출 동작을 합니다. 지금은 button이 form 밖에 독립적으로 있어서 눌러도 아무 일도 일어나지 않습니다.

다음 Commit을 위한 준비

  1. POST 요청 — 폼의 데이터를 서버로 보내는 HTTP 방식. <form method="post">로 사용합니다.
  2. @PostMapping — POST 요청을 처리하는 어노테이션
  3. @RequestParam — 폼에서 넘어온 데이터를 Java 메서드에서 받는 방법
  4. <form action="..."> — 폼 데이터를 어떤 URL로 보낼지 지정하는 HTML 속성
  5. DB 저장 — 데이터를 받은 다음 어딘가에 저장해야 합니다. 이때 Repository와 JPA가 등장합니다.
ADDITIONAL Q&A
수업 후 추가 질문
Q1

BoardApplication 클래스는 뭐야?

@SpringBootApplication
public class BoardApplication {
    public static void main(String[] args) {
        SpringApplication.run(BoardApplication.class, args);
    }
}

Spring Boot 앱의 시작점입니다. Java 프로그램은 항상 main() 메서드에서 시작됩니다. SpringApplication.run()이 호출되는 순간 Spring이 깨어나면서:

  • 내장 Tomcat(웹 서버) 실행
  • @Controller, @Service 등이 붙은 클래스들을 스캔해서 Bean으로 등록
  • 8080 포트 열고 HTTP 요청 대기
@SpringBootApplication 하나에 세 가지 역할이 합쳐져 있습니다. 지금은 "앱 켜는 스위치"로만 이해하면 됩니다.
Q2

BoardController를 com.study.board 안에 만든 이유?

BoardApplication.java와 같은 패키지이거나 그 하위여야 하기 때문입니다.

@SpringBootApplication은 자신이 위치한 패키지와 그 하위 패키지만 스캔합니다.

com.study.board             ← BoardApplication 위치
com.study.board.controller  ← BoardController 위치 (하위 ✅)
com.other.controller        ← 여기 두면 스캔 안 됨 ❌
com.study.board.controller에 뒀기 때문에 Spring이 자동으로 발견해서 Bean으로 등록한 것입니다. 바깥에 뒀다면 @Controller를 붙여도 Spring이 인식하지 못합니다.
Q3

HTTP 요청이 뭐야?

브라우저와 서버가 대화하는 규칙(프로토콜)입니다. 브라우저가 서버에 "이거 줘"라고 보내는 메시지가 HTTP 요청(Request), 서버가 "여기 있어"라고 돌려주는 메시지가 HTTP 응답(Response)입니다.

요청에는 방식(Method)이 있습니다:

방식 언제 쓰나 예시
GET 데이터를 가져올 때 주소창에 URL 입력, 링크 클릭
POST 데이터를 보낼 때 폼 제출, 회원가입, 게시글 작성
브라우저 주소창에 localhost:8080/board/write를 치면 → GET 요청이 날아갑니다.
Q4

왜 templates/ 안에 있어야 Thymeleaf가 찾을 수 있어?

Thymeleaf가 그렇게 설정되어 있기 때문입니다. application.properties에 명시하지 않아도 Spring Boot가 기본값으로 정해줍니다:

prefix  = classpath:/templates/
suffix  = .html

즉 "boardwrite"를 반환하면 Thymeleaf가 자동으로 이렇게 조합합니다:

"boardwrite" 반환
    ↓ prefix + 반환값 + suffix
templates/boardwrite.html
    ↓ classpath = src/main/resources/
src/main/resources/templates/boardwrite.html
원하면 application.properties에서 경로를 바꿀 수 있지만, 관례를 따르는 게 좋습니다.
Q5

컨트롤러에서 return하면 무조건 그 파일을 찾아? Thymeleaf 때문인가?

반은 맞고 반은 틀립니다.

String을 반환했을 때 View 이름으로 해석하는 것은 Spring MVC(ViewResolver)의 역할입니다. Thymeleaf는 그 파일을 실제로 렌더링하는 역할입니다.

return "boardwrite"
    ↓
Spring MVC (ViewResolver) → "templates/boardwrite.html 찾아"
    ↓
Thymeleaf → 파일 읽어서 HTML로 변환 후 브라우저에 전달

무조건은 아닙니다. @ResponseBody를 붙이면 문자열 그 자체를 응답으로 보냅니다:

@GetMapping("/test")
@ResponseBody
public String test() {
    return "hello";   // 브라우저에 "hello" 텍스트가 그대로 출력됨
                      // templates/hello.html 을 찾지 않음
}
@RestController를 쓰면 모든 메서드에 @ResponseBody가 자동 적용됩니다. 나중에 API 만들 때 씁니다.
Q6

GET이든 POST든 Spring은 무조건 Controller로 보내? 여러 개면? 이름 같은 게 있으면?

요청이 오면 DispatcherServlet이 받아서 URL + Method가 일치하는 메서드를 찾아 실행합니다.

Controller가 여러 개여도 괜찮습니다. Spring이 모든 Controller를 미리 스캔해서 URL 매핑 테이블을 만들어 둡니다:

GET  /board/write  →  BoardController.boardWriteForm()
POST /board/write  →  BoardController.boardWriteSave()   // 아직 없음
GET  /board/list   →  BoardController.boardList()        // 아직 없음
URL + Method 조합이 같은 게 있으면?
앱 실행 시점에 에러가 납니다. 중복 매핑은 허용되지 않습니다.
URL은 같지만 Method가 다른 것은?
괜찮습니다. 같은 URL이지만 GET/POST로 구분해서 쓰는 것이 일반적인 패턴입니다.
@GetMapping("/board/write")   // GET → 작성 폼 화면 보여주기
public String boardWriteForm() { ... }

@PostMapping("/board/write")  // POST → 실제 저장 처리
public String boardWriteSave() { ... }
Q8

컨트롤러 A, B가 있을 때 — 중복 매핑 기준이 뭐야?

기준은 클래스가 아니라 URL + Method 조합입니다.

A 컨트롤러
  @GetMapping("/test")   → GET /test

B 컨트롤러
  @PostMapping("/test")  → POST /test  ✅ (Method 달라서 괜찮음)
  @GetMapping("/test")   → GET /test   ❌ (A에 이미 있음 → 앱 실행 시 에러)
왜 에러가 나는가?
Spring이 내부적으로 만드는 매핑 테이블에서 GET /test가 중복되면 어느 걸 실행해야 할지 결정할 수 없습니다. 그래서 앱 자체가 뜨지 않습니다. 메서드 이름이 같든 다르든 상관없고, URL + Method가 겹치는지만 봅니다.
Q9

어노테이션을 안 붙이면 "일반 클래스"라는 게 뭐야?

Java에서 클래스는 그냥 설계도입니다. 어노테이션이 없으면 Spring은 이 클래스의 존재를 모릅니다.

// 어노테이션 없음
public class BoardController {
    public String boardWriteForm() {
        return "boardwrite";
    }
}

// 사용하려면 개발자가 직접 해야 함
BoardController controller = new BoardController();
controller.boardWriteForm();
일반 클래스 @Controller 붙인 클래스
객체 생성 개발자가 new로 직접 Spring이 자동으로
URL 연결 불가능 Spring이 자동으로
Spring 인식 모름 Bean으로 등록해서 관리
@Controller, @Service, @Repository의 공통점이 바로 이것입니다. "이 클래스를 Spring이 관리하는 Bean으로 등록해줘"라는 신호입니다.
Q10

DispatcherServlet과 HandlerMapping이 뭐야?

DispatcherServlet은 Spring의 교통 정리 담당자입니다. 모든 HTTP 요청은 무조건 DispatcherServlet을 먼저 통과합니다. 혼자 다 처리하는 게 아니라 요청을 보고 적절한 곳에 위임합니다.

브라우저 요청
    ↓
DispatcherServlet ← 모든 요청의 첫 번째 관문
    ↓ "이 URL 누가 처리해?"
HandlerMapping 에게 물어봄
    ↓ "처리할 메서드 찾았어"
해당 Controller 메서드 실행
    ↓ "결과 화면 찾아줘"
ViewResolver 에게 위임
    ↓
브라우저에 응답

HandlerMapping은 URL + Method 조합을 보고 어떤 클래스의 어떤 메서드가 처리할지 찾아주는 역할입니다. 앱이 시작될 때 @Controller 클래스들을 스캔해서 매핑 테이블을 미리 만들어 두고, 요청이 들어오면 테이블에서 찾아 DispatcherServlet에게 알려줍니다.

Q11

@GetMapping을 안 붙이면 매핑이 안 돼?

맞습니다. 매핑 자체가 안 됩니다.

@Controller
public class BoardController {

    // @GetMapping 없음
    public String boardWriteForm() {
        return "boardwrite";
    }
}

이 메서드는 HandlerMapping 테이블에 등록되지 않습니다. 어떤 URL로 접속해도 이 메서드는 절대 실행되지 않습니다.

@Controller와 @GetMapping의 역할 차이
@Controller → "이 클래스를 Spring이 관리해줘"

@GetMapping → "이 메서드를 이 URL에 연결해줘"

둘 다 있어야 실제로 요청을 받을 수 있습니다.
Q12

Spring은 내부적으로 어떻게 View 파일을 찾아?

1. 요청 들어옴
    ↓
2. DispatcherServlet 수신
    ↓
3. HandlerMapping 으로 어떤 Controller 메서드인지 찾음
    ↓
4. 해당 메서드 실행 → "boardwrite" 반환
    ↓
5. ViewResolver 목록을 순서대로 조회
    → ThymeleafViewResolver: "templates/boardwrite.html 있어?"
    ↓
6. 파일 존재하면 Thymeleaf가 HTML 파싱 및 렌더링
    ↓
7. 완성된 HTML을 HTTP 응답으로 브라우저에 전달
ViewResolver는 여러 개가 등록될 수 있고, 우선순위 순서대로 시도합니다. 파일을 찾지 못하면 다음 ViewResolver를 시도하고, 전부 실패하면 500 에러가 납니다.
🟢 DispatcherServlet과 ViewResolver 내부는 나중에 공부할 내용입니다. 지금은 위 흐름을 그림으로 기억해두는 것으로 충분합니다.
