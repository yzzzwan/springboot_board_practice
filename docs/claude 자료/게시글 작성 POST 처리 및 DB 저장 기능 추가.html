STEP 03

핵심 코드 설명

Board.java NEW
@Entity
@Data
public class Board {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer Id;
    private String title;
    private String content;
}
  • 초보자 게시글 데이터의 틀입니다. id, 제목, 내용 세 칸짜리 양식.
  • Java / Lombok @Data는 Lombok 라이브러리의 어노테이션입니다. 이 어노테이션 하나가 아래 코드 전체를 자동으로 만들어줍니다.
@Data (Lombok)이 자동으로 만들어주는 것

@Data 없이 직접 작성해야 할 코드

public String getTitle() { return title; }
public void setTitle(String title) { this.title = title; }
public String getContent() { return content; }
public void setContent(String content) { this.content = content; }
// + toString(), equals(), hashCode() ...

@Data 사용 시

@Data
public class Board {
    private String title;
    private String content;
    // 끝. 나머지는 Lombok이 처리
}

getter/setter는 JPA가 필드 값을 읽고 쓸 때 필요하고, Spring의 데이터 바인딩(form → 객체)도 setter를 통해 동작합니다. Lombok 없이도 직접 쓰면 되지만 코드가 길어집니다.

⚠️ @Data는 DB 칼럼 기준이 아니라 Java 필드 기준으로 getter/setter를 만듭니다. DB를 전혀 모르고 그냥 "이 클래스에 필드가 몇 개 있는지"만 봅니다.

@Transient — DB 칼럼 제외하기

클래스에 필드를 추가했을 때 DB 칼럼으로 만들고 싶지 않다면 @Transient를 붙입니다.

@Transient 없음 → DB 칼럼 생성
private String tempValue;
// → board 테이블에 temp_value 칼럼 생성
// → getter/setter 생성
@Transient 있음 → DB 무시
@Transient
private String tempValue;
// → DB 칼럼 생성 안 함
// → getter/setter는 생성됨

반대로 필드는 있는데 DB 칼럼이 없고 @Transient도 없으면? → 앱 시작은 되지만 INSERT/SELECT 시 SQL 에러가 납니다 (ddl-auto=none인 경우). 이번에 겪었던 에러가 이 케이스입니다.

  • Spring/JPA @Entity는 "이 클래스를 DB 테이블과 연결하겠다"는 선언입니다. @Id는 기본키(PK), @GeneratedValue(IDENTITY)는 "DB가 자동으로 생성하는 값을 쓸 것"이라고 JPA에 알려줍니다.

    DB에 auto increment를 설정해도 @GeneratedValue가 없으면 JPA는 "id를 내가 직접 채워야 한다"고 생각합니다. id 없이 save()하면 에러가 납니다. DB 설정과 JPA 설정 두 군데 모두 맞춰야 정상 동작합니다.
    DB auto increment만 DB는 값을 만들지만 JPA가 모름 → id 없이 save() 시 에러
    @GeneratedValue만 JPA는 알지만 DB가 안 만듦 → INSERT 시 에러
    둘 다 설정 INSERT 후 DB가 생성한 id를 JPA가 받아와서 객체에 채움 ✓
⚠️ @Entity를 붙인다고 테이블이 자동으로 만들어지는 것은 아닙니다.

테이블을 실제로 생성할지는 application.properties의 spring.jpa.hibernate.ddl-auto 설정이 결정합니다.

create 앱 시작 시 기존 테이블 DROP 후 새로 CREATE
update 테이블 없으면 CREATE, 있으면 구조 변경만 (데이터 유지)
validate 테이블 구조가 Entity와 맞는지 검증만, 변경 없음
none 아무것도 안 함 (MariaDB 같은 외부 DB의 기본값)

현재 프로젝트에서 SQL 에러가 났던 것도 이 설정과 관련이 있습니다.

BoardRepository.java NEW
public interface BoardRepository extends JpaRepository<Board, Integer> {
    // 비어 있음
}
  • 초보자 "Board를 DB에 저장하고 꺼내오는 도구"입니다. 내부가 비어 있는데도 save() 같은 기능을 사용할 수 있습니다.
  • Java class가 아닌 interface입니다. 인터페이스와 클래스는 역할이 다릅니다.
인터페이스 vs 클래스
클래스 (class)

설계도 + 실제 구현이 모두 있음. new로 인스턴스 생성 가능.

class BoardService {
  public void write() {
    // 구현이 여기 있음
  }
}
인터페이스 (interface)

규격(틀)만 정의. 구현은 다른 곳에서. 직접 new 불가.

interface BoardRepository
  extends JpaRepository {
  // 구현 없음, 틀만
}

BoardRepository가 인터페이스인 이유는 Spring Data JPA가 런타임(앱 실행 시)에 구현체를 자동으로 만들어주기 때문입니다. 개발자가 구현체를 직접 작성할 필요가 없고, 그래서 내부가 비어 있어도 됩니다.

  • Spring/JPA JpaRepository<Board, Integer>를 상속하면 아래 메서드들이 자동으로 생깁니다. SQL을 한 줄도 작성하지 않아도 됩니다.
메서드 설명 SQL 예시
save(entity) 저장 (없으면 INSERT, 있으면 UPDATE) INSERT INTO board ...
findById(id) id로 단건 조회, Optional 반환 SELECT * FROM board WHERE id=?
findAll() 전체 목록 조회, List 반환 SELECT * FROM board
deleteById(id) id로 삭제 DELETE FROM board WHERE id=?
count() 전체 데이터 개수 SELECT COUNT(*) FROM board
existsById(id) 해당 id 존재 여부 (true/false) SELECT COUNT(*) ... WHERE id=?

더 복잡한 쿼리가 필요할 때는 메서드명 규칙(findByTitle(...))이나 @Query로 직접 SQL을 추가할 수도 있습니다.

BoardService.java NEW
@Service
public class BoardService {

    @Autowired
    private BoardRepository boardRepository;

    public void write(Board board) {
        boardRepository.save(board);
    }
}
  • 초보자 write()라는 메서드 하나를 가진 클래스입니다. 호출하면 DB에 저장합니다.
  • Spring — Bean @Service를 붙이면 Spring이 이 클래스를 Bean으로 등록합니다.
Bean이란?

Spring이 직접 생성하고 관리하는 객체를 Bean이라고 합니다.

일반 Java 객체

개발자가 직접 new로 생성. 사용 후 개발자가 관리.

BoardService svc =
  new BoardService();
Spring Bean

Spring이 자동으로 생성, 관리, 필요한 곳에 주입.

@Service
class BoardService {
  // Spring이 알아서 관리
}

@Service, @Repository, @Controller, @Component 중 하나라도 붙으면 Spring Bean으로 등록됩니다. 아무것도 안 붙이면 Spring은 이 클래스의 존재를 모릅니다.

  • Spring — @Autowired @Autowired는 Spring에게 "이 타입의 Bean을 찾아서 여기에 넣어줘"라고 요청하는 어노테이션입니다.
@Autowired — 자동 의존성 주입

개발자가 직접 new로 객체를 만들지 않아도, Spring이 알맞은 Bean을 찾아 자동으로 연결해줍니다. 이것을 의존성 주입(Dependency Injection)이라고 합니다.

@Autowired 없이 (일반 Java)
// 개발자가 직접 생성
BoardRepository repo =
  new BoardRepository(); // ❌ 인터페이스는 new 불가
@Autowired 사용 (Spring)
@Autowired
private BoardRepository repo;
// Spring이 알아서 찾아서 넣어줌 ✓

Spring이 @Autowired를 보면 "BoardRepository 타입의 Bean을 컨테이너에서 찾아서 이 필드에 넣어라"를 수행합니다. Bean이 등록되어 있지 않으면 앱 시작 시점에 에러가 발생합니다.

  • 설계 지금은 한 줄이라 왜 Service가 필요한지 의문이 들 수 있습니다. 나중에 유효성 검사, 알림 발송 등 비즈니스 로직이 생기면 Service가 그 자리를 담당합니다.
BoardController.java MODIFIED
@Autowired
private final BoardService boardService;

public BoardController(BoardService boardService) {
    this.boardService = boardService;
}

@PostMapping("/board/writepro")
public Board boardWritePro(Board board) {
    boardService.write(board);
    return board;
}

생성자 주입으로 BoardService를 받아 사용합니다. 단, 이 코드에는 버그가 두 개 있습니다 (STEP 7 참고).

boardwrite.html MODIFIED
<form action="/board/writepro" method="post">
    <input name="title" type="text" placeholder="제목">
    <textarea name="content" placeholder="내용"></textarea>
    <button type="submit">작성</button>
</form>

form의 name="title", name="content"가 전송되면 Spring이 Board 객체의 필드에 자동으로 채워줍니다. 이것을 데이터 바인딩이라고 합니다. Board의 setter(@Data가 만들어준)를 통해 값이 들어갑니다.

STEP 04

왜 이렇게 작성했는가?

왜 Controller → Service → Repository로 나누는가?

역할을 비유로 먼저 잡으면 이렇습니다.

손님 (브라우저)
    ↓ 주문
웨이터 (Controller)  ← HTTP 요청을 받고 응답만 담당
    ↓ 주문 전달
주방장 (Service)    ← 실제 처리 로직 담당
    ↓ 재료 요청
냉장고 (Repository) ← DB에서 데이터 꺼내고 넣는 역할
    ↓
DB

각 계층의 담당 범위:

Controller URL 매핑, 파라미터 받기, View 반환
Service 조건 처리, 계산, 유효성 검사, 여러 Repository 조합
Repository 저장, 조회, 삭제 (DB 접근만 담당)

지금은 Service가 한 줄이라 의미 없어 보이지만, 나중에 로직이 생기면 이렇게 됩니다.

public void write(Board board) {
    if (board.getTitle() == null) {          // 유효성 검사
        throw new Exception("제목 없음");
    }
    board.setTitle(board.getTitle().trim()); // 공백 제거
    boardRepository.save(board);             // 저장
    mailService.send("새 글 등록됨");        // 알림 발송
}

이 로직이 Controller 안에 있으면 Controller가 비대해집니다. 그리고 각 계층은 바로 아래 계층만 호출합니다. Controller가 Repository를 직접 호출하거나, Repository가 Service를 호출하는 일은 없습니다.

왜 BoardRepository를 interface로 만들었는가?
JpaRepository 자체가 인터페이스이고, 인터페이스는 인터페이스로만 상속(extends)할 수 있습니다. Spring Data JPA가 앱 실행 시점에 이 인터페이스를 보고 구현체를 자동으로 생성해주기 때문에 개발자는 구현 코드를 작성하지 않아도 됩니다.
왜 form에 name 속성이 필요한가? Board에 없는 name이 넘어오면 어떻게 되는가?
name이 없으면 이 필드의 데이터는 서버로 전송되지 않습니다. Spring은 name 값과 Board 클래스의 필드명을 매칭해서 setter를 호출해 값을 넣어줍니다.

name="title" → board.setTitle("입력값")
name="content" → board.setContent("입력값")

Spring은 매핑할 때 "맞으면 넣고, 없으면 넘긴다" 방식으로 동작합니다.
상황 결과
name="title" → Board.title 있음 setTitle() 호출해서 값 채움
name="create_date" → Board에 없음 무시 (에러 없음)
Board.content 있는데 form에 없음 null 로 들어옴
왜 @Autowired를 쓰는가? 직접 new 하면 안 되는가?
BoardRepository는 인터페이스이므로 직접 new가 불가능합니다. 그리고 Spring이 만들어준 구현체(Bean)를 직접 찾아서 new 하는 것은 불가능합니다. @Autowired를 쓰면 Spring이 이미 관리 중인 Bean을 찾아서 자동으로 연결해줍니다. 또한 같은 Bean을 여러 곳에서 재사용할 수 있어 메모리 효율도 좋습니다.

Bean 등록(@Service 등)과 @Autowired는 한 쌍입니다.
@Service → Bean 등록 (Spring이 관리 시작)
    ↓
@Autowired → 등록된 Bean을 꺼내서 연결

Bean이 없으면 @Autowired가 꺼낼 게 없어서 에러
@Autowired가 없으면 Bean이 있어도 자동 연결 안 됨

STEP 07

초보자가 하기 쉬운 착각

"@Entity를 붙이면 테이블이 자동으로 생긴다"
→ @Entity는 "이 클래스를 테이블과 연결하겠다"는 선언일 뿐입니다. 실제 테이블 생성은 spring.jpa.hibernate.ddl-auto 설정이 결정하며, MariaDB/MySQL의 기본값은 none이라 자동 생성되지 않습니다.
"인터페이스 내부가 비어 있으면 아무 기능도 없다"
→ JpaRepository를 상속하는 인터페이스는 Spring Data JPA가 런타임에 구현체를 자동으로 만들어줍니다. 빈 인터페이스처럼 보여도 save(), findAll() 등을 바로 사용할 수 있습니다.
"@Autowired가 있으면 무조건 주입된다"
→ 주입받으려는 타입의 Bean이 등록되어 있어야 합니다. @Service, @Repository 같은 어노테이션이 없어서 Bean이 아닌 경우 앱 시작 시 "No qualifying bean" 에러가 납니다.
"Board board 파라미터는 개발자가 직접 만들어서 넘긴다"
→ Spring이 form의 name 속성을 보고 Board 객체를 만들어 필드를 자동으로 채워줍니다. name 속성이 없거나 필드명이 다르면 해당 값은 null이 됩니다.
⚠️ 이번 코드에 버그가 두 개 있습니다.

1. @Autowired + final 충돌 — @Autowired는 리플렉션으로 필드에 값을 넣는데, final은 생성 후 변경 불가. 이 둘은 함께 쓸 수 없습니다. @Autowired를 제거하고 생성자 주입만 남기면 됩니다.

2. return board — @Controller에서 객체를 반환하면 Spring이 "board"라는 이름의 View를 찾으려 해서 오류 발생. public String boardWritePro(...)로 바꾸고 return "redirect:/board/list"를 반환해야 합니다.

  • JpaRepository 상속 — 기본 DB 작업 메서드 자동 제공
  • Bean — Spring이 관리하는 객체 (@Service, @Repository, @Controller)
  • @Autowired — Bean을 자동으로 주입받는 방법
  • Controller → Service → Repository 3계층 구조
  • form의 name 속성과 Entity 필드 바인딩

🟡 개념만 이해

  • Lombok / @Data — getter/setter/toString 자동 생성, 데이터 바인딩에 필요
  • spring.jpa.hibernate.ddl-auto — 테이블 자동 생성 여부 설정
  • JpaRepository 제공 메서드 종류 (save, findAll, findById, delete 등)
  • 데이터 바인딩 — form name ↔ Entity 필드 setter 자동 매핑

🟢 나중에 공부

  • JPA 영속성 컨텍스트 — JPA가 객체를 관리하는 내부 메커니즘
  • @Transactional — DB 작업의 원자성 보장
  • Spring Bean 생명주기 (생성 → 의존성 주입 → 초기화 → 소멸)
  • 생성자 주입 vs 필드 주입의 차이와 권장 방식
STEP 09

오늘 배운 것

  • @Entity는 클래스를 DB 테이블과 연결하겠다는 선언이고, 실제 테이블 생성은 ddl-auto 설정이 결정한다.
  • @Data(Lombok)는 getter/setter/toString을 자동으로 생성해준다. Spring의 데이터 바인딩도 setter를 통해 동작한다.
  • 인터페이스는 규격(틀)만 정의하고, 클래스가 실제 구현을 담당한다.
  • JpaRepository를 상속한 인터페이스는 Spring Data JPA가 런타임에 구현체를 자동 생성해주므로 내부가 비어 있어도 save(), findAll() 등을 사용할 수 있다.
  • Spring이 관리하는 객체를 Bean이라고 하며, @Service/@Repository/@Controller를 붙이면 Bean으로 등록된다.
  • @Autowired는 Spring이 알맞은 Bean을 찾아 자동으로 주입해준다. 개발자가 직접 new 하지 않아도 된다.
  • Spring 웹 앱은 Controller → Service → Repository 3계층으로 역할을 나눈다.
STEP 10

이해도 확인 질문

정답은 바로 알려드리지 않습니다. 생각해보고 답해보세요.

  1. BoardRepository가 비어 있는데 어떻게 save()를 쓸 수 있나요?

    JpaRepository를 상속하면 Spring Data JPA가 save(), findAll(), findById() 등의 구현체를 런타임에 자동으로 만들어줍니다. 개발자가 SQL을 직접 작성하지 않아도 됩니다.

  2. @Service를 BoardService에서 지우면 어떻게 될까요?

    Spring이 BoardService를 Bean으로 등록하지 않습니다. BoardController에서 @Autowired로 BoardService를 주입받으려 할 때 "No qualifying bean of type BoardService" 에러가 나며 앱이 실행되지 않습니다.

  3. Controller에서 Repository를 직접 호출하지 않고 Service를 거치는 이유는 무엇인가요?

    역할 분리 때문입니다. Controller는 HTTP 요청/응답만 담당하고, Service는 비즈니스 로직(유효성 검사, 알림 발송 등)을 담당합니다. 나중에 로직이 복잡해져도 Controller가 비대해지지 않습니다.

  4. <input name="title">에서 name을 지우면 어떻게 될까요?

    name이 없는 필드의 값은 서버로 전송되지 않습니다. Board 객체의 title이 null로 들어오고, DB에도 null이 저장됩니다.

  5. MariaDB를 쓰는데 ddl-auto 설정을 안 하면 테이블이 자동으로 만들어질까요?

    안 만들어집니다. MariaDB 같은 외부 DB의 ddl-auto 기본값은 none이라 아무것도 하지 않습니다. 테이블을 자동 생성하려면 create 또는 update로 설정해야 합니다.
