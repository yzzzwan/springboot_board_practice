Step 1

이번 Commit 한눈에 보기

이번 commit에서는 DB에 저장된 게시글 전체 목록을 화면에 출력하는 기능을 만들었습니다.

/board/list 주소로 접속하면, Service가 DB에서 게시글을 전부 꺼내 Controller에 넘기고, Controller는 그 데이터를 HTML 템플릿으로 전달합니다.

HTML은 Thymeleaf를 이용해 게시글 수만큼 테이블 행을 자동으로 반복 생성합니다. 이제 게시판의 CRUD 중 C(Create)와 R(Read)가 완성되었습니다.

Step 2

무엇이 변경되었는가

BoardService.java — boardList() 추가

public List<Board> boardList(){
    return boardRepository.findAll();
}
  • 어떤 파일? 비즈니스 로직 담당 계층
  • 왜 추가? 게시글 목록을 가져오는 로직을 Service에 위치시키기 위해
  • 역할: Repository에 "전부 꺼내줘" 요청을 대신함
  • 연결: BoardRepository의 findAll()을 호출 → Board 객체 목록 반환

BoardController.java — boardlist() 추가

@GetMapping("board/list")
public String boardlist(Model model){
    model.addAttribute("list", boardService.boardList());
    return "boardlist";
}
  • 어떤 파일? HTTP 요청을 받아 처리하는 계층
  • 왜 추가? /board/list GET 요청을 처리하기 위해
  • 역할: Service에서 받은 목록을 Model에 담아 HTML 템플릿으로 전달
  • 연결: boardService.boardList() 호출 → 결과를 "list"라는 이름으로 Thymeleaf에 전달

boardlist.html — Thymeleaf로 목록 반복 출력

<tr th:each="board: ${list}">
    <td th:text="${board.id}"></td>
    <td th:text="${board.title}"></td>
</tr>
  • 어떤 파일? 화면 담당 View 파일
  • 왜 추가? Controller에서 받은 list를 테이블로 표시하기 위해
  • 역할: list에 담긴 Board 객체 수만큼 <tr> 행을 자동 반복 생성
Step 3

핵심 코드 설명

Model model 파라미터

public String boardlist(Model model){

초보자 관점

Controller가 HTML에 데이터를 전달하는 "택배 상자" 같은 것입니다.

Java 관점

Model은 Spring이 제공하는 인터페이스입니다. 메서드 파라미터에 선언만 하면 Spring이 자동으로 객체를 만들어 넣어줍니다.

Spring 관점

Controller 메서드가 끝날 때, Model에 담긴 데이터는 자동으로 Thymeleaf 템플릿으로 전달됩니다. 직접 넘길 필요가 없습니다.

model.addAttribute("list", ...)

model.addAttribute("list", boardService.boardList());

택배 상자에 물건을 넣으면서 이름표를 붙이는 것입니다.

  • 이름표: "list"
  • 물건: boardService.boardList()가 돌려준 List<Board>

HTML에서는 이 이름표를 그대로 사용합니다: ${list}

findAll()

return boardRepository.findAll();

Java 관점

findAll()은 List<Board>를 반환합니다. Board 객체가 여러 개 담긴 리스트입니다.

Spring/JPA 관점

BoardRepository가 JpaRepository를 상속받고 있기 때문에 findAll()은 자동으로 제공됩니다. 직접 구현하지 않아도 됩니다. JPA가 내부적으로 SELECT * FROM board를 실행합니다.

th:each

<tr th:each="board: ${list}">

Java의 for 루프와 같습니다.

// Java로 표현하면:
for (Board board : list) {
    // <tr> 한 줄 만들기
}
  • ${list} → Controller가 Model에 담은 게시글 목록
  • board → 반복할 때마다 꺼낸 게시글 하나
Step 4

왜 이렇게 작성했는가?

왜 Controller가 Repository를 직접 호출하지 않는가?

// 현재 코드: Controller → Service → Repository
model.addAttribute("list", boardService.boardList());

// 이렇게도 가능하지만...
model.addAttribute("list", boardRepository.findAll());

지금은 단순히 findAll() 하나지만, 나중에 정렬, 검색, 페이징, 권한 체크 같은 로직이 추가되면 전부 Service에 모아야 합니다. Controller에 섞이면 코드가 점점 복잡해집니다.

왜 Model을 사용하는가?

Controller에서 HTML로 데이터를 넘기는 방법이 Model입니다. Spring MVC에서 이 역할을 담당하도록 설계된 공식 방법입니다.

model.addAttribute("키", 값) 형태로 담으면, Thymeleaf는 ${키}로 꺼내 씁니다.

Step 7

초보자가 하기 쉬운 착각

findAll()은 내가 만든 게 아닌데 왜 동작하나? BoardRepository가 JpaRepository<Board, Integer>를 상속받고 있기 때문입니다. JpaRepository 안에 이미 findAll(), save(), deleteById() 등이 구현되어 있습니다. 상속만 해도 자동으로 사용 가능합니다.
model.addAttribute("list", ...)의 "list"는 아무 이름이나 써도 되나? 네, 아무 이름이나 써도 됩니다. 단, HTML에서 꺼낼 때 같은 이름을 써야 합니다.

model.addAttribute("boardData", ...); → HTML에서도 ${boardData}로 꺼내야 함
th:each는 Java의 for문과 완전히 같은가? 기능은 같지만 동작 시점이 다릅니다. th:each는 Thymeleaf가 HTML을 렌더링할 때 서버에서 처리합니다. 브라우저에 도달할 때는 이미 반복이 완료된 순수 HTML입니다.

Step 9

오늘 배운 것

  • Model은 Controller에서 View(HTML)로 데이터를 전달하는 객체다.
  • model.addAttribute("키", 값)으로 담고, HTML에서 ${키}로 꺼낸다.
  • JpaRepository의 findAll()은 직접 구현하지 않아도 DB 전체 조회를 처리한다.

  • 이제 게시판에 쓰기(C)와 읽기(R) 두 기능이 모두 갖춰졌다.
Step 10

이해도 확인 질문

드래그해서 정답을 확인하세요.

  1. model.addAttribute("list", ...) 에서 "list"를 "boardList"로 바꾸면 HTML도 어떻게 바꿔야 하나요?

    Thymeleaf에서 ${list}로 꺼내던 부분을 ${boardList}로 바꿔야 합니다. th:each="board: ${boardList}"처럼 키 이름이 정확히 일치해야 데이터가 전달됩니다.

  2. findAll()을 직접 구현하지 않았는데 왜 동작하나요?

    BoardRepository가 JpaRepository를 상속하기 때문입니다. Spring Data JPA가 런타임에 findAll(), save(), findById() 등의 구현체를 자동으로 만들어줍니다. 개발자는 인터페이스만 선언하면 됩니다.

  3. th:each="board: ${list}"에서 board는 무엇을 의미하나요?

    반복문에서 현재 순번의 Board 객체를 담는 변수입니다. Java의 for(Board board : list)와 같은 개념입니다. 이름은 자유롭게 바꿀 수 있고, 같은 tr 태그 안에서 board.id, board.title 등으로 접근합니다.

  4. Controller에서 Service를 거치지 않고 Repository를 바로 호출하면 안 되는 이유는?

    기능은 동작하지만 역할이 섞입니다. Controller는 HTTP 요청/응답만 담당해야 하고, 비즈니스 로직(유효성 검사, 권한 확인 등)은 Service에 있어야 합니다. 나중에 로직이 복잡해질수록 Controller가 비대해지고 유지보수가 어려워집니다.

  5. /board/list로 접속했을 때 코드가 실행되는 순서를 처음부터 끝까지 말해보세요.

    브라우저 GET 요청 → BoardController.boardlist() → BoardService.boardList() → BoardRepository.findAll() → DB SELECT → List<Board> 반환 → model.addAttribute("list", ...) → boardlist.html 렌더링 → 브라우저에 HTML 응답
